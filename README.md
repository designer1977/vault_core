# VAULT_CORE

**A client-side cryptographic utility engine for generating secure keys, passwords, and secrets. Nothing leaves your browser.**

Live site: [vaultcore.tools](https://vaultcore.tools/)

---

## Summary

Vault Core is a zero-latency, zero-transmission cryptographic key and password generator that runs entirely in your browser. No server-side processing. No telemetry. No logs. No cookies. No localStorage. Every operation happens client-side using the browser's native Web Crypto API.

This repository contains the client-side application and developer tools for running Vault Core locally.

## Key Features

- Zero Transmission — The built-in Network Monitor confirms 0 outgoing requests and 0 bytes sent during all operations
- CSPRNG-Powered — Uses `window.crypto.getRandomValues()` (the same cryptographic primitive used for TLS and disk encryption)
- No Data Stored — No cookies, no localStorage, no sessionStorage, no IndexedDB. Refresh the page and everything is gone
- Multiple Output Formats — Strong passwords, 256-bit hex keys, 128-bit hex keys, JWT secrets, API keys, UUID v4
- Entropy Quality Metrics — Real-time display of entropy quality, character scale, and maximum entropy per generation
- Technical Manifest — Built-in documentation showing exactly which APIs are used and why, with a full security logic breakdown
- Key Type Comparison — Guidance on which key type suits different use cases (API auth, JWT signing, database encryption, etc.)
- Cryptography Glossary — Educational reference covering CSPRNG, entropy, and key types

## Security Architecture

Vault Core generates all cryptographic material using the browser's native `window.crypto.getRandomValues()` API, which draws from the operating system's cryptographically secure random number generator (CSPRNG).

What this means:
- Random values are generated by the OS kernel's entropy pool — not JavaScript `Math.random()` or any pseudo-random algorithm
- The same cryptographic primitive used by browsers for TLS handshakes and disk encryption
- Generation happens entirely client-side. No request is made to any server during key generation

## What Vault Core does NOT do

- Does not transmit generated keys or passwords to any server
- Does not store generated values anywhere (browser storage or otherwise)
- Does not log or track user activity
- Does not use analytics, telemetry, or fingerprinting
- Does not load external resources during generation

The built-in Network Monitor verifies these claims in real-time — watch it during generation to confirm 0 bytes transmitted.

## Running locally — Quick start

### Prerequisites

- Node.js (v18 or later)
- Your Base44 app credentials (if you need to run parts of the app that require them)

### Clone and install

1. Clone the repo

   ```bash
   git clone https://github.com/designer1977/vault_core.git
   cd vault_core
   ```

2. Install dependencies

   ```bash
   npm install
   ```

### Environment

Create an `.env.local` file at the project root with your Base44 environment variables if required by your development workflow:

```
VITE_BASE44_APP_ID=your_app_id
VITE_BASE44_APP_BASE_URL=your_backend_url

# Example values used by Base44
# VITE_BASE44_APP_ID=cbef744a8545c389ef439ea6
# VITE_BASE44_APP_BASE_URL=https://my-to-do-list-81bfaad7.base44.app
```

> Note: Core generation features do not require these credentials; they are only needed for Base44 builder integration or any optional backend tooling.

### Start the dev server

```bash
npm run dev
```

Open http://localhost:3000 (or the port shown by your dev server) to view the app.
